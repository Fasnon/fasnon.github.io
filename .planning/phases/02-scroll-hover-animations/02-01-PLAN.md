**Step 1: Install @vueuse/motion**

```bash
npm install @vueuse/motion
```

Verify install succeeds and check version (expect 3.x).

**Step 2: Register MotionPlugin in main.ts**

Update `src/main.ts` to:

```typescript
import { createApp } from 'vue'
import { MotionPlugin } from '@vueuse/motion'
import './assets/styles.css'
import App from './App.vue'

const app = createApp(App)
app.use(MotionPlugin)
app.mount('#app')
```

Key: `app.use(MotionPlugin)` must come before `app.mount('#app')`.

**Step 3: Extend tailwind.config.js with card-hover shadow**

Add `boxShadow` to `theme.extend` in `tailwind.config.js`:

```javascript
boxShadow: {
  'card-hover': '0 8px 24px -4px rgba(136, 158, 122, 0.30), 0 4px 8px -2px rgba(60, 61, 55, 0.10)',
},
```

The RGBA values use tame-green (136, 158, 122) and mahogany (60, 61, 55) from the existing palette. This shadow is consumed by Plan 02 for card hover effects.

**Step 4: Add custom CSS to styles.css**

After the Tailwind directives in `src/assets/styles.css`, add:

```css
@layer components {
  .link-underline {
    @apply relative inline-block;
  }
  .link-underline::after {
    content: '';
    @apply absolute bottom-0 left-0 h-[2px] w-full;
    background: currentColor;
    transform: scaleX(0);
    transform-origin: left center;
    transition: transform 200ms ease-out;
  }
  .link-underline:hover::after {
    transform: scaleX(1);
  }
}

/* Accessibility: Override @vueuse/motion inline opacity:0 for reduced-motion users.
   @vueuse/motion sets opacity:0 as inline style at mount time and does NOT
   check prefers-reduced-motion internally. This ensures content is visible. */
@media (prefers-reduced-motion: reduce) {
  [style*="opacity"] {
    opacity: 1 !important;
    transition: none !important;
  }
}
```

The `link-underline` class creates an animated underline that slides in from left using `::after` pseudo-element with `scaleX` transform. This is consumed by Plan 02 for NavBar link hover effects. Tailwind utilities alone cannot animate pseudo-element transforms.

The `prefers-reduced-motion` media query provides a global safety net. Per-element `motion-reduce:opacity-100` classes (added in Task 2) are the primary mechanism, but this global rule catches any edge cases.

  <action>
Add `v-motion` directives with explicit `:initial` and `:visibleOnce` props to the root element of each below-the-fold section view. Use explicit control (not presets) to enforce the locked 500ms ease-out timing.

**CRITICAL:** Do NOT apply v-motion to `AboutMe.vue`. Per user decision, above-the-fold content renders instantly with no fade.

**For each section view (Experiences, Projects, Writeups, Contact):**

Add these attributes to the outermost element (the `<div>` or `<section>` root):

```html
v-motion
:initial="{ opacity: 0 }"
:visibleOnce="{
  opacity: 1,
  transition: { duration: 500, ease: 'easeOut' }
}"
class="... motion-reduce:opacity-100"
```

Key implementation details:
- Use `:visibleOnce` (camelCase), NOT `:visible-once` (kebab-case) — kebab-case has a known bug (GitHub Issue #108)
- `duration: 500` enforces the user's 500ms requirement
- `ease: 'easeOut'` makes elements "arrive and settle" per user decision
- Add `motion-reduce:opacity-100` to the existing class list — this Tailwind utility overrides the inline `opacity: 0` set by @vueuse/motion's `:initial` state for users who prefer reduced motion
- The whole section fades as one unit — no stagger, no per-card delays (per user decision)
- Trigger once only — `:visibleOnce` ensures the element stays visible permanently after first viewport entry

**Experiences.vue** — Add to the root `<div>`:
```html
<div
  v-motion
  :initial="{ opacity: 0 }"
  :visibleOnce="{ opacity: 1, transition: { duration: 500, ease: 'easeOut' } }"
  class="min-h-[calc(100vh-100px)] max-sm:min-h-[calc(100vh-56px)] flex flex-col pl-40 pt-8 pr-16 bg-muted-green motion-reduce:opacity-100"
```
